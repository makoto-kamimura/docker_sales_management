# カード決済（Stripe）の設定手順

カード決済（注文・投げ銭・定期便）を動かすための Stripe 側の設定と、動作の確認の手順をまとめる。
仕様は [README.md](../../README.md)（[8.1節 カード決済](../../README.md#81-カード決済)・[第14章 サブスクリプション](../../README.md#14-サブスクリプション)・[20.7節 カード決済（Stripe）](../../README.md#207-カード決済stripe)）を参照。

本番サーバー固有の手順（サーバーへの設定の置き方・反映・WAF）は、公開しない手元の `*.local.md` に分けている。

## 前提

- カード情報はこのサービスで受け取らない。入力は Stripe の画面（Checkout / Customer Portal）で行い、結果は Webhook で反映する。
- API が読む環境変数は次の3つ。`STRIPE_SECRET_KEY` と `STRIPE_WEBHOOK_SECRET` の両方がそろわないと、カード決済は無効になる（画面にカードの選択肢を出さず、カードの API は `503`）。

| 環境変数 | 値 |
|---|---|
| `STRIPE_SECRET_KEY` | シークレットキー（`sk_test_...` / `sk_live_...`） |
| `STRIPE_WEBHOOK_SECRET` | Webhook の署名シークレット（`whsec_...`） |
| `APP_BASE_URL` | Web の公開 URL（決済画面からの戻り先。例：`https://<サイトのドメイン>`） |

- まずテストモードで設定・確認し、実際に売上を受けるときに本番モードへ切り替える。テストモードと本番モードでは、キー・Webhook・カスタマーポータルの設定がすべて別になる。
- ダッシュボードの表記は版によって多少違う（例：「Webhook」が「イベントの送信先」になっている）。

## 1. アカウントとテストモード

1. https://dashboard.stripe.com/register でアカウントを作る（国は日本）。テストモードは本人確認なしで使える。
2. ダッシュボード右上の切り替えで「テスト環境（サンドボックス）」にする。2〜4章はテスト環境で行う。

## 2. API キー

- 「開発者 › API キー」で「シークレットキー」（`sk_test_...`）を控え、`STRIPE_SECRET_KEY` に設定する。
- 公開可能キー（`pk_...`）は使わない（Stripe.js を使わない作りのため）。
- キーはチャット・チケット・コミットに貼らない。サーバーの環境変数にだけ置く。

## 3. カスタマーポータル

定期便の「支払いカードの変更」で使う。設定を一度保存しないと、ポータルを開く API がエラーになる。

「設定 › Billing › カスタマーポータル」（テストモード：https://dashboard.stripe.com/test/settings/billing/portal）で次のようにして保存する。

| 項目 | 設定 | 理由 |
|---|---|---|
| 支払い方法の更新 | オン | この機能の目的 |
| 請求書の履歴 | オン（任意） | |
| サブスクリプションのキャンセル | オフ | 解約はサイトから行う（ポータルで解約されても Webhook で反映はされる） |
| プランの変更・数量の変更 | オフ | 価格を申し込みごとに作る作りなので、切り替え先のプランがない |

## 4. Webhook の送信先

「開発者 › Webhook › エンドポイントを追加（送信先を追加）」で作る。

- エンドポイント URL：`https://<サイトのドメイン>/api/v1/webhooks/stripe`
- ペイロードの形式：スナップショット（通常のイベント）。thin イベントではない
- API バージョン：既定（最新）のままでよい（請求書は新旧どちらの形式でも読む）
- 受け取るイベント（6つ）：

| イベント | 反映すること |
|---|---|
| `checkout.session.completed` | 注文を入金確認へ / 投げ銭を入金確認済みに / 定期便をお届け中に |
| `checkout.session.expired` | 注文・投げ銭は払い直せるようにする / 申し込み手続き中の定期便を取り消す |
| `invoice.paid` | 定期便のお届け分の注文を作り、入金確認へ |
| `invoice.payment_failed` | 定期便を「支払いの確認待ち」に |
| `customer.subscription.updated` | 定期便の状態（一時停止など）と次回お届け日 |
| `customer.subscription.deleted` | 定期便を解約済みに |

作成後に「署名シークレット」（`whsec_...`）を表示し、`STRIPE_WEBHOOK_SECRET` に設定する。

環境変数を設定して API を再起動したら、`GET /api/v1/payment_settings` が `{"card_enabled":true}` を返すことを確かめる。

## 5. 開発環境で試す場合

開発環境（`platform/docker-compose.yml`）では、公開 URL の代わりに Stripe CLI で Webhook を転送する。

```bash
stripe login
stripe listen --forward-to localhost/api/v1/webhooks/stripe
# 表示された whsec_... を platform/.env の STRIPE_WEBHOOK_SECRET に入れ、api を再起動する
```

`platform/.env` には `STRIPE_SECRET_KEY`（テストキー）・`STRIPE_WEBHOOK_SECRET`・`APP_BASE_URL=http://localhost` を入れる。

## 6. テストモードでの確認

テストカード（有効期限は未来の日付、セキュリティコード・郵便番号は任意）：

| 用途 | カード番号 |
|---|---|
| 成功 | `4242 4242 4242 4242` |
| 3D セキュアの認証あり | `4000 0027 6000 3184` |
| 拒否 | `4000 0000 0000 0002` |

確認すること：

1. 物販品をカードで注文する → 注文詳細が「入金確認」になり、在庫が確定出庫される。
2. 3Dデータだけの注文をカードで払う → 「完了」になり、ダウンロードできる。
3. 決済画面で戻る（中止）→ 注文は「注文受付」のまま残り、注文詳細の「カードで支払う」から払い直せる。
4. 拒否のカード → 決済画面でエラーになり、注文は「注文受付」のまま。
5. 0円の商品を含む注文で、カードの投げ銭 → 入金確認済みになる。
6. 定期便をカードで申し込む → 1回目の注文ができる。一時停止・再開・スキップ・解約が、Stripe の購読（「Billing › サブスクリプション」）にも反映される。「支払いカードの変更」でポータルが開く。
7. Stripe の Webhook の配信履歴が、すべて `204` になっている。

- 2回目以降の自動の請求はすぐには起こせない（テストクロックは Stripe の顧客の作成時に付ける必要があり、このサイトが作る顧客には付けられない）。
- 請求ごとの注文の作成は API のテスト（`spec/requests/api/v1/card_payments_spec.rb`）で確かめている。実地では、毎週プランを申し込んで1週間後の注文を見る。

うまくいかないとき：

| 症状 | 見るところ |
|---|---|
| 配信履歴が `400` | 署名シークレットが送信先（テスト / 本番）のものと合っているか |
| 配信履歴が `503` | `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` の両方が API に渡っているか |
| 配信履歴が `403`（API のログに届いていない） | 手前のプロキシ・WAF で止まっていないか |
| 「支払いカードの変更」が開けない | カスタマーポータルの設定を保存したか（3章） |
| 決済後に画面が「注文受付」のまま | 少し待って再読み込み。直らなければ配信履歴と API のログ |

## 7. 本番モードへの切り替え

1. ダッシュボードの「アカウントを有効化」で、事業者情報・本人確認・入金先の銀行口座・明細書の表記（ローマ字・カナ）を登録する。
2. 特定商取引法に基づく表記のページの URL `https://<サイトのドメイン>/legal/tokushoho` を登録する（日本のアカウントの有効化で求められる）。
   - 先に管理画面「設定 › ショップ情報」で、販売事業者名・運営統括責任者・メールアドレス・所在地と電話番号（または「請求があれば開示」）・方針を入力する。足りない項目があると、公開ページに「（準備中）」と出る。
   - 個人で「請求があった場合には遅滞なく開示します」の書き方を使う場合は、Stripe の審査で認められるかを申請時に確認する。
3. 本番モードで2〜4章をやり直す（`sk_live_...`、新しい Webhook の送信先と `whsec_...`、カスタマーポータルの設定）。
4. サーバーの環境変数を本番の値に差し替え、API を再起動する。
5. 実際の決済では Stripe の手数料（国内カードで3.6%程度）がかかる。テストカードは使えない。
